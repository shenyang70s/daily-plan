# AI native 工作流

用户已批准按检查建议执行：统一入口与确认执行、连续修改、真实研究上下文、扩展日历/投稿/提醒。复用当前 React/NestJS/SQLite 与领域服务，保留已有手动入口作为兜底，不重写业务基础。

方案选择：扩展现有编排器，使用有界结构化上下文、不可变方案及显式确认。相比前端串行调用多个 API，此方式支持批量事务和执行审计；相比开放式自主代理，不引入任意工具或无限循环。沿用当前工作目录，保留前序未提交实现；不创建会遗漏未提交基础的新 checkout，不提交或发布。

自然语言入口：Today、全局助手、收集箱、全部任务、日历、投稿统一进入同一组件；页面可传当前资源 ID，服务端校验归属。保留手工维护。

上下文：仅当前用户，明确列出数量/日期范围与截断；包括任务标题/类型/状态/优先级/时长/期限/课题与工作块、课题名称、固定日程、投稿阶段与来源中的真实截止节点、提醒政策。排除凭据、URL、自由备注与其他用户记录。跟随当前输入读取新快照；引用的目标必须来自该快照。查询继续由服务端工具读取。

连续修改：请求携带 parentRunId，由服务端按用户读取最近八轮输入和结果，包括已执行状态。每轮是新方案，不能把已执行操作当作待执行方案重复提交。追问答复与“换个时间”等修改承接历史。

白名单方案：创建/修改任务，安排/移动工作块，创建/修改固定事件，创建/修改课题，创建/修改投稿阶段与下一步、准备任务拆解，以及创建/调整/取消提醒。新投稿节点只能使用用户明确提供的期限，不生成会议事实。新建记录通过有界 new:N 引用在同批中设置提醒/关联课题。默认空档计算由确定性算法负责，AI 提出任务拆分与顺序/约束。无可用时段显示未安排，不能声称已排程。

执行：最多十二项操作；服务端保存标准化方案及实际影响。确认 API 仅接受 runId 与确认标志，不接受任意客户端操作；使用既有服务、所有权、expectedVersion 和冲突检查。独立外层事务中的服务适配器复用同一事务，不改变全局数据库嵌套策略。一次全部成功或全部回滚；runId 唯一执行结果防重，重复确认只回放结果。执行结果/操作审计与业务写入同事务。旧方案在继续修改后失效，冲突或过期通过自然语言重新生成。

界面：方案摘要/原因、每项前后影响与时间、假设/上下文范围、确认/取消；可继续输入修改方案。成功展示真实结果链接。错误保留输入和方案。AI 关闭或不可用仍有手动维护。

边界：不自动删除业务记录、不自行更新权威会议截止来源、不后台自主变更、不网络抓取用户 URL。模型固定 DeepSeek，现有限流、取消和恢复继续有效。有限上下文无法保证完整全局优化，截断必须可见。

验证：有针对性的 schema/上下文隔离/连续修改/批量原子执行/版本冲突/提醒引用/重复确认/旧方案失效测试，现有 AI 与日历回归，前后端构建与隔离浏览器检查。真实 DeepSeek 仅对合成数据有限冒烟。
